## 二、逐项说明

### 1. `test-v22-calculator.mjs`（69）

- 覆盖：取余（含 0 与负数）、行步、宫位取象结构、基础计算、边界（1/1/1、6/6/6、999/999/999）、**216 种三宫组合**索引一致性、大数取模；
- 使用 `calculator.js` 的逻辑副本；数据口径与运行时已于 2026-10-01 统一（见第三节）。

### 2. `test-v22-jiang-pai.mjs`（93）

- 覆盖：子时 / 午时 / 丑时样例、六亲关系（生克）、解卦文本与空数据边界、12 时辰轮转、六神 / 六星固定映射；
- 六星使用「木星 / 火星 / 土星 / 金星 / 水星 / 天星」（与运行时一致）。

### 3. `test-v22-dao-pai.mjs`（104）

- 覆盖：死六神固定映射、活六神 12 时辰轮转、六亲、解卦文本（`calculator.js` 长版）与 null / 空数据边界、隔位排地支公式、全时辰覆盖；
- 运行时道传解卦与 `calculator.js` 均为长版「【道传·死活六神双轨合参】…」（2026-10-01 统一）。

### 4. `test-v22-lunar.mjs`（46）

- 覆盖：`getShiChen` 24 小时映射与边界（-1 / 24 / 25）、`toChineseLunar` 样例（含闰月）、`formatTime`；
- 【6】加载真实 `src/core/lunar.js`（`node:vm`），用 7 个公开可核对日期（1900 起点 / 春节 / 闰二月 / 闰六月 / 除夕）验证转换与闰月标记；这是唯一加载运行时库的测试。

### 5. `test-v22-data.mjs`（267）

- 覆盖：六宫 / 六亲 / 六神 / 六星数据完整性、地支五行、组合断语抽样（37 / 216 条）、交叉引用一致性；
- 空亡释义与运行时一致（「谋事落空，徒劳无功」，2026-10-01 统一）。

### 6. `test-compat-full.mjs`（144）

- 覆盖兼容矩阵：旧 V2.2 纯数组、新 V2.2 纯数组、旧 V3.0 信封、新 V3.0 信封、新 V3.0「导出 V2.2 格式」；
- 验证 `answers` 与 `finalShen` 两种结构的归一化，以及渲染层防御逻辑（模拟实现，不导入运行时模块）。

### 7. `test-v22-protected-release.cjs`（8）

- 覆盖：受保护包存在、loader 格式、解码后包含核心计算与江氏逻辑、已完成混淆、不直接暴露核心函数名、不包含外部脚本引用、解码后语法可解析；
- 直接引用 `scripts/build-protected.cjs` 的 `decodePayload`；除本节与 `test-v22-lunar.mjs`【6】外，其余核心测试不引用仓库代码。

### 8. 文档链接检查（`check:docs`）

- 扫描全部 Markdown 的相对链接（跳过 `http(s)`、`file:`、锚点），发现死链即失败；历史文档中的本机路径链接按规则跳过。

## 三、数据口径与测试的关系（2026-10-01 已统一）

- 运行时由 `domain-adapter.js` 用 `browser-core.js` 覆盖 `calculator.js` 的同名函数；空亡释义、六星命名、六神写法（腾蛇）与道传解卦文本已在三处对齐（运行时 / `calculator.js` 与知识速查 / 测试副本）；
- 5 个核心脚本仍是**自包含逻辑副本**（例外：`test-v22-lunar.mjs` 的【6】节加载真实 `lunar.js`），只提供规则回归参考，不代表真实页面行为验收；
- 修改任何数据口径时，必须同步 `src/core/browser-core.js`、`src/core/calculator.js` 与对应测试副本，并更新本清单。

## 四、维护规则

- 修改排盘规则或数据口径：必须同步更新对应测试与[小六壬历史文化与排盘方法](../产品/小六壬历史文化与排盘方法.md)；
- 新增测试：登记到本清单，并接入 `test:all` 或 `test:compat` / CI，不允许「只存在于本地」；
- 断言数量变化：同步 [docs/版本说明.md](../../docs/版本说明.md) 与[项目代码与文档统计](../治理/项目代码与文档统计.md)；
- 测试脚本内的汇总文案必须与实际断言数一致（受保护包测试已修正为动态计数）。
