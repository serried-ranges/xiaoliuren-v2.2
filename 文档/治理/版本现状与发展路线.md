# 版本现状与发展路线

> 更新时间：2026-10-05（按当前源码、`package.json`、CI 配置与实际测试入口核对；历史方案不作为当前操作步骤）
> 用途：V2.2 的**现状唯一入口**——本仓库是什么、边界在哪、怎么维护、要不要继续演进。
> 相关：[未来发展纲领](未来发展纲领.md)（方向与门槛）｜[待办事项与方案进度](待办事项与方案进度.md)（进度唯一入口）

## 一句话结论

V2.2 是**冻结的历史兼容基线**：只读对照、仅接受正确性 / 安全 / 兼容类修复，不发布、不跟进 V3；唯一活跃开发与网页发布源是主项目 V3（`x6ren.cn`）。

## 版本现状

| 项目 | 定位 | 状态与边界 |
|---|---|---|
| 本仓库 · `2.2.0` | 历史兼容基线（简洁版） | 归档冻结；可核对旧排盘结果、旧数据格式；不新增功能 |
| 主项目 V3 | 唯一活跃开发与网页发布源 | 功能、视觉、发布均只在 V3 进行 |
| 小红书离线版（独立仓库） | 平台离线工具 | 独立源码、依赖、构建与打包；与本仓库不共享构建时源码 |
| 资料站 `x6ren.cn` | V3 的公开镜像 | 只接收 V3 导出的发布包；V2.2 不参与发布 |

## 数据与联网边界

- 数据只保存在浏览器本地（localStorage 按身份命名空间隔离）；应用自身不发起网络请求、不收集或上传数据；
- 唯一外跳是用户主动点击「更多 → 切换标准」跳转 `https://x6ren.cn/`（浏览器导航，不携带本地数据）；
- 受保护构建只提高源码阅读门槛，不是密钥保护；仓库不包含任何密钥。

## 维护规则

1. 新需求与功能只在 V3 进行；本仓库不新增功能、不跟进视觉；
2. 只接受：正确性修复（排盘结果、农历、数据兼容）、安全与隐私修复、浏览器兼容与可访问性修复、测试与文档补充；
3. 每次修改后运行完整门禁（见[接手与重启 §2](接手与重启.md)）；
4. 不改变 `dist/`、`release/` 的生成方式；`release/index.html` 重建后与 Git 不一致属正常现象；
5. 数据格式（存储键名、导入导出结构）保持兼容，任何变更必须先更新[数据兼容与迁移](../../docs/数据兼容与迁移.md)与兼容测试；
6. 文档改动遵循「同一事实一个权威入口」；移动文档后运行 `npm run check:docs`；
7. 对外发布（部署、导出交付物、接入新平台）必须逐次确认；常规代码推送按已配置的**一主两备**链路执行（一次 `git push` 推三仓 + Actions 兜底镜像，见[根 README](../../README.md)）；
8. `history/` 是历史证据，不是当前共享核心；引用其中结论前先对照当前源码。

## 推荐发展路线

- **阶段一（当前）· 保持归档**：不开发；仅按需修复兼容 / 安全问题，并维持 CI 全绿；
- **阶段二 · 按需核对**：用于旧排盘结果、旧备份格式的人工对照（配合 `dist/index.html` 与测试）；
- **阶段三 · 解冻（需决策）**：仅当满足[未来发展纲领](未来发展纲领.md)第六节的决策门槛，且完成[接手与重启 §5](接手与重启.md)的全部准备后，才转为活跃维护；
- 不做：第三条活跃产品线、后端与账号体系、与 V3 的双向同步、为「更完整」而新增排盘流派（当前规则已固定）。
