## 2. 恢复环境与全量验收（约 5 分钟）

前置条件：Node.js（CI 使用 22；14 以上即可运行脚本）、可联网安装依赖。

```powershell
git clone git@github.com:serried-ranges/xiaoliuren-v2.2.git   # 或使用已有本地目录
cd xiaoliuren-v2.2
npm ci                  # 安装 Vite 等开发依赖（仅开发/构建用）
npm run check           # 12 个源码模块语法检查；无输出即通过
npm run check:docs      # 文档相对链接检查
npm run test:all        # 5 个核心脚本；2026-09-30 实测 571 项断言全部通过
npm run test:compat     # V2.2 ↔ V3.0 数据兼容（144 用例）
npm run build           # 生成 dist/index.html（明码单文件，735,742 字节）
npm run build:protected # 生成 release/index.html（混淆保护版，959,395 字节）
npm run test:protected  # 受保护包检查（8 条断言）
```

验收标准：以上命令全部退出码为 0；任何一步失败先记录为**基线问题**再动手修改。

注意事项：

- `dist/index.html` 可由源码逐字节复现（哈希一致，`git status` 不脏）；
- `release/index.html` **每次构建字节都不同**（混淆带随机性，大小基本相同），重建后 `git status` 显示变更属正常；不要用哈希或 `git diff` 判断发布包新旧，一律以 `npm run test:protected` 为准；
- 数字（断言数、产物大小）以命令输出为准；快照口径记录在[docs/版本说明.md](../../docs/版本说明.md)与[项目代码与文档统计](项目代码与文档统计.md)。

## 4. 已知事项与历史债务（重启前必读）

完整清单与状态见[待办事项与方案进度 §三](待办事项与方案进度.md)；以下为接手时最容易踩的关键项：

| 事项 | 现状 | 影响与建议 |
|---|---|---|
| 受保护构建不可复现 | `release/index.html` 每次构建字节不同 | 不要把「构建产物与 Git 不一致」当成源码漂移；用 `test:protected` 验证 |
| 模式持久化未生效 | 每次打开固定回到古法（`main.js` 初始化决策） | 不要按旧文档的「刷新后保持」描述行为；如需恢复见[待办 #1](待办事项与方案进度.md) |
| 运行时与 `calculator.js` 存在数据差异 | `domain-adapter` 覆盖同名函数（空亡释义、六星命名、道传解卦文本） | 改算法前先读 [docs/开发者指南.md §3](../../docs/开发者指南.md)；不要只改 `calculator.js` |
| 核心测试是自包含副本 | 5 个核心脚本不导入运行时模块，可能漂移 | 只作规则回归参考；页面行为需按 [docs/开发者指南.md §4.5](../../docs/开发者指南.md)人工检查 |
| 农历转换无测试覆盖 | `solarToLunar` 未被测试调用；`lunar.js` 无显式年份钳制 | 改动农历逻辑必须补样例测试 |
| PWA 名称残留 | manifest 与 apple title 仍标注 V2.1.2 | 属已知问题（待办 #3），修复前不要据此判断版本 |
| 历史文档含本机死链 | `history/V2.2/AUDIT_*.md` 内 `file:///D:/...` 为迁仓前路径 | 仅作证据留存，不要照抄；链接检查已将其列为跳过项 |
| 占位样式文件 | `styles/feedback.css`、`styles/template.css` 仅含注释 | 删除需同步修改 `index.html` 的 `<link>`；否则勿动 |
| 依赖休眠风险 | Vite / javascript-obfuscator 为开发期锁定版本 | 长期停更后 `npm ci` 需联网；升级依赖属于「不接受的重构」，确需升级须先过决策门槛 |
| 数字口径曾出错 | 旧文档把 5 个脚本合计断言写为 267（实为 571） | 已于 2026-09-30 校正；今后数字以命令输出为准 |

## 5. 解冻重启的决策门槛

想把本仓库从「归档」转为「活跃」，须先逐条满足（参照主项目治理口径）：

1. **明确维护者与范围**：谁长期维护、维护到什么程度（仅兼容修复 / 恢复功能开发）；
2. **明确重启目标与验收**：例如「只做旧结果核对工具」或「承接 V3 迁移的某个功能」，并给出回滚方式；
3. **更新状态声明**：修订[归档说明](../../归档说明.md)与 [CONTRIBUTING](../../CONTRIBUTING.md)，撤销「冻结」表述；
4. **保持门禁**：CI 关卡（`check → check:docs → test:all → test:compat → build → build:protected → test:protected`）继续全绿，并补齐真机 / 浏览器人工验收记录；
5. **从 V3 迁移功能时**：走主项目的「功能迁移单」流程，不直接复制 V3 代码，也不承诺双向同步；
6. **对外发布逐次确认**：本仓库不发布线上页面；任何导出、推送与发布动作都必须单独确认。

未满足以上条件前，保持归档状态，只做 §2 的验收与边界内修复。
