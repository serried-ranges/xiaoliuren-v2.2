## 3. 与其他目录的分工

| 目录 | 只写什么 | 不写什么 |
|---|---|---|
| `docs/` | 当前代码事实、命令、结构、使用说明 | 不写治理方向与历史叙事 |
| `文档/`（本目录） | 治理、产品与质量资料 | 不复制实现细节 |
| `history/` | 已结束的历史资料与证据 | 不作为当前操作指令 |

## 4. 维护规则

- 文档只描述本仓库事实；跨项目引用使用绝对链接（GitHub URL），不写跨仓相对路径；
- **同一事实只保留一个权威入口**（地图见[接手与重启 §3](治理/接手与重启.md)）；其他位置写摘要 + 链接；
- 数字（断言数、产物大小）以命令输出为准，快照必须标注实测日期；数字变化时同步 [docs/版本说明.md](../docs/版本说明.md) 与[根 README](../README.md)；
- 移动 / 重命名文档后运行 `npm run check:docs`（CI 也会检查）；
- 新增文档先归位：方向与规范 → `治理/`；功能与叙事 → `产品/`；测试与验收 → `质量与审计/`。
