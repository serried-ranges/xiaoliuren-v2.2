# 小六壬排盘 V2.3.0 功能迭代方向规划

> **归档状态**：这是 2026-08-13 的历史草案，不代表当前排期、功能承诺或后续版本号。当前活跃版本为 V2.2 与固定版本号的 V3.0.0；是否采纳其中建议必须结合当前源码重新评估。

> 版本：ROADMAP V2.3.0 Draft  
> 日期：2026-08-13  
> 基于：V2.2.0 模块化架构（src/core/ui/store/utils/styles）  
> 原则：**先稳住核心体验，再扩展生态能力；P0 必须做，P1 争取做，P2 视用户反馈调整**

---

## 📊 优先级定义

| 等级 | 含义 | 目标完成时间 |
|------|------|-------------|
| **P0 - 核心必做** | 影响最多用户 / 安全 / 体验短板，不做会被反复吐槽 | V2.3.0 发布前必须完成 |
| **P1 - 功能增强** | 新能力扩展 / 差异化竞争力，直接提升付费意愿或用户粘性 | V2.3.0 内尽量完成，可顺延至 V2.3.x |
| **P2 - 体验打磨 / 前瞻** | 锦上添花 / 未来铺垫 / 长期维护性 | 时间够就做，不够就 V2.4.0 |

## 🚀 8 大迭代方向

---

### 🌐 方向 1：多语言国际化支持（i18n）【P0 - 高优】

**为什么必须做**：当前所有中文字符串散落在 9 个 JS + 4 个 CSS 中（代码审计 Issue #4 已记录），海外华人、日本、韩国、东南亚用户完全用不了。增加一套语言就意味着所有字符串替换位置要改一遍，越早重构代价越低。

**V2.3.0 方案**：

```
架构：一个字典文件 + 一个全局 t() 函数 + 语言切换器（右上角菜单下）
├── src/i18n/
│   ├── zh-CN.js   // 简体中文（默认，999+ 条）
│   ├── zh-TW.js   // 繁体中文（台湾/香港/海外华人，1:1 简繁转换+术语校正）
│   ├── en-US.js   // 英文（海外用户、留学生、AI 英文 prompt 对接）
│   └── ja-JP.js   // 日文（日本易学爱好者相当多，可后续版本补）
└── src/utils/i18n.js  // initLang / t() / switchLang
```

**实施步骤**：
1. 从现有代码中提取所有「中文字符串常量」形成 i18n 词条（约 1000 条：菜单文案/按钮/标签/提示/错误/模式名/神名/解卦文本）
2. 神名、六亲、六神等专业术语做「不可翻译保护 key」（如 大安=DaAn/大安/だいあん，保留中文+拼音+假名多列）
3. `safeLS.setItem('xll_lang', 'zh-CN')` 持久化语言偏好
4. 三套 AI Prompt 模板同时支持对应语言（英文 Prompt 直接喂给 Claude/GPT 英文模型，省一次翻译成本和语义漂移）

**预计代码量**：新增 4-5 个文件（i18n 模块+4 语言包），修改 9 个 JS 文件中硬编码中文为 `t('key')`。V2.3.0 完成后新增语言只需加一个 YAML/JSON 文件即可，无需改源码。

### 📱 方向 2：移动端适配深度优化【P0 - 高优】

**为什么必须做**：95%+ 用户用手机打开（尤其是微信/tmp 场景），当前移动端体验是"能用但不够舒服"（审计 Issue #5）：折叠区触控热区 <44px、iOS 100vh 橡皮筋顶起布局、软键盘弹出时底部输入控件被遮挡、微信内置浏览器 UI 适配不完整。

**V2.3.0 具体落地清单**：

| 优化项 | 现状 | 目标 |
|-------|------|------|
| 触控热区 | 折叠按钮 20×20，卡片点击 <40px | 所有可点击元素最小 **44×44px** 触控目标（WCAG AA 标准）|
| 100vh 布局 | CSS `height:100vh` 在 iOS Safari 变 110vh，有底部黑条 | 使用 `100dvh`（动态视口单位）+ CSS `env(safe-area-inset-bottom)` 安全区 |
| 软键盘遮挡 | 问念输入时底部计数器/提交按钮弹到键盘下看不到 | `visualViewport.resize` 事件动态调整 `margin-bottom` + 自动滚动到聚焦控件 |
| 微信内置浏览器 | 返回手势 / 前进手势冲突 | `touch-action: manipulation` 全局设置；阻止非交互区域误触 |
| iOS PWA 模式 | 添加到主屏后状态栏样式不匹配 `apple-mobile-web-app-status-bar-style` | 状态栏 `black-translucent` + 顶部 padding 适配 |
| 字体适配 | 部分 Android 手机宋体很丑 | 字体栈加入 `-apple-system, "PingFang SC", "Noto Sans SC"`，避免回落到宋体 |
| 动画 | 折叠动画 300ms 低帧率 | 改成 CSS transform/opacity 硬件加速动画，禁用高消耗 box-shadow 动画 |
| 横屏体验 | 几乎没适配（卡片溢出） | `@media (orientation: landscape)` 专门媒体查询 |

**实施步骤**：先在 Chrome DevTools 开启设备模拟（iPhone SE / Galaxy S24 / iPad Mini）逐个页面过一遍，按优先级 P0→P2 改。

### 📄 方向 3：排盘结果导出为 PDF / 长图片【P0 - 高优】

**为什么必须做**：用户现在只能截图，AI 解卦结果无法完整保存为文件，"发给朋友"或"保存到相册"体验断裂。

**V2.3.0 方案**：

```
排盘结果卡片顶部加一个 ⤓ 导出按钮，弹出下拉选择：
├── 保存为长图片（PNG，高清 2x DPR，适合发朋友圈/聊天）
│    → 技术：html2canvas（已用 Canvas 证明可用，复用 QR 模块基础）
├── 保存为 PDF（A4 竖版，适合打印/存档，包含所有三宫 + AI 解卦 JSON 排版）
│    → 技术：jsPDF + html2canvas 合成
└── 复制为 Markdown（导出给 Obsidian / Notion / 语雀知识库）
```

**字段包含**：起卦时间、三数、问念、三宫神名、终落宫、AI 解卦 5 字段结果（如果有）、模式徽章。整页尺寸 ~1080×N 高度自适应。

**注意**：由于 V2.2.0 是 file:// 单文件交付，PDF/图片导出 lib 必须内嵌打包到最终单 HTML 中（可懒加载触发时才注入 `<script>`），不依赖网络 CDN。

### 🏪 方向 4：提示词模板市场（云端同步）【P1】

**为什么要做**：现在 V2.2.0 模板只能本地 import/export JSON，用户间无法分享好模板；新手找不到"最准的模板"；优秀的用户模板无法沉淀到产品生态中。

**V2.3.0 方案**：

```
菜单入口：AI 解析弹窗 → 模板 Tab → 「🏪 模板市场」按钮
├── 分类浏览：古法类 / 江氏类 / 道传类 / 感情类 / 事业类 / 综合类
├── 模板内容：作者名 + 点赞数 + 适用场景描述 + 预览文本（10 行）+ 一键「加载到我的模板」
├── 上传模板：用户可将自己本地模板一键「匿名投稿」到市场（人工审核或词过滤）
└── 离线兜底：模板市场 JSON 大清单打包内嵌进主 HTML 一份作为默认种子（10-20 个精品模板），无网时也能用
```

**云端实现**（如需）：最简单的方式是部署一个 GitHub Gist 或 Cloudflare Workers KV（免费额度够几十万请求），每天定时拉取更新覆盖本地内嵌清单，不需要自建后端服务器。

**风险控制**：投稿模板内容经关键词过滤（涉政/暴恐/色情）+ 审核黑名单机制；敏感词直接拒绝提交。

### 🔍 方向 5：历史记录全文搜索 + 标签分类【P1】

**为什么要做**：V2.2.0 用户用 1 个月后历史记录可能达 200+ 条，目前只有线性滚动，无法搜索特定问念、特定宫位、特定时间范围。

**V2.3.0 方案**：

```
历史记录区顶部加一个 🔍 搜索栏 + 🏷️ 标签筛选：
├── 搜索：输入关键词 → 实时过滤问念文本/AI解卦文字/反馈文字，支持拼音模糊
├── 标签系统：每条记录支持加 1-3 个自定义标签（感情/事业/健康/财运/学习/其他）
├── 高级筛选：模式限定(古法/江氏/道传) + 日期范围 + 终落宫神名 + 星级反馈分
└── 数据导出：筛选结果一键导出为 CSV/JSON，便于外部分析
```

**数据结构**：在 V2.2.0 `xll_history` localStorage 条目基础上，每条加 `{ tags: string[], searchTextLower: string }` 两个字段，向后兼容（升级时一次性后台任务补齐，不影响旧记录）。

### 🛡️ 方向 6：安全加固专项【P1】

**为什么要做**：代码审计 Issue #2/#6/#7 已列出 XSS / LS 明文 / CSP 缺失三个安全隐患。虽然 V2.2.0 是纯单文件静态 HTML，但用户问念可能涉及很隐私的内容（感情、健康、诉讼等），必须加强防护。

**V2.3.0 具体落地**：

| 隐患 | 现状 | V2.3.0 加固方案 |
|------|------|----------------|
| XSS 注入 | 用户输入嵌入 innerHTML 时部分已 escape（模板）但部分未走统一 | V2.2.0 已加 `window.htmlEscape()` 工具函数（⚠️ 2026-08-30 代码精简中已移除，因未被任何模块调用），V2.3.0 所有 innerHTML 用户内容必须全部经过它；审计脚本 grep `innerHTML =` 每一处人工确认 |
| CSP 缺失 | 无 Content-Security-Policy，第三方脚本可随意注入 | `<meta http-equiv="Content-Security-Policy" content="default-src 'self' 'unsafe-inline' 'unsafe-eval' data: blob:;">` 加进 `<head>`；后续逐步去掉 unsafe-* |
| localStorage 明文 | 问念/反馈/模板全明文存，浏览器拿到电脑就能看 | 本地存储值统一做 **XOR + Base64** 轻量加密（非强加密意义在于防随手翻看到明文；密钥基于浏览器 UserAgent hash 生成，不同设备无法互读）|
| safeLS 容量上限 | V2.2.0 缓存整页时已有 QuotaExceeded 处理，但其他小写入没处理 | 所有 safeLS.setItem 调用统一走 wrapper，异常时 Toast 提示不崩溃 |
| 第三方外链 | 目前没有外链（好），但未来二维码等可能 | 所有 `<a target="_blank">` 必须带 `rel="noopener noreferrer nofollow"` |
| 点击劫持保护 | 无 X-Frame-Options | `<meta http-equiv="X-Frame-Options" content="DENY">` 禁止 iframe 嵌入（防点击劫持钓鱼页面套壳）|

### ✅ 方向 7：完整 PWA 离线支持 + Service Worker【P2】

**为什么是 P2**：V2.2.0 已有 manifest + SVG 图标（PWA 一半能力），但没有 Service Worker，断网重开可能资源未缓存。但由于最终交付是 file:// 单文件 HTML，Service Worker 只能在 HTTP/HTTPS 环境下生效（Chrome 等浏览器 file:// 默认禁用 SW），所以边际收益不如上面 6 项高，放 P2。

**V2.3.0 落地方案**：

```
├── sw.js（内嵌进单 HTML 或懒加载注入）
│   ├── 静态资源预缓存：CSS 内嵌 HTML / JS 内嵌 HTML，全部 Cache First
│   ├── runtime 缓存：Canvas 二维码生成 Blob URL、历史记录 LS 缓存配合
│   └── 离线兜底页：断网时显示"小六壬离线模式已启用，核心排盘功能正常"
├── index.html head 增加 serviceWorker.register() 注册代码
└── 更新检测：SW updatefound 事件触发时 Toast "🔄 发现新版本，请刷新页面以升级"
```

**作用范围**：只对 GitHub/AtomGit Pages（HTTP/HTTPS 在线版）以及用户自己开的本地服务器生效；file:// 用户仍用单文件 HTML 原生离线。

### 🎨 方向 8：深色主题 + 多种国风皮肤切换【P2】

**为什么是 P2**：锦上添花，美观类需求，不影响核心功能准确性。但夜间使用的用户（晚上占卜问事很多）对暗模式呼声很高，一旦推出留存率显著提升。

**V2.3.0 方案**：

```
右上角更多菜单 → 「🎨 主题」→ 3 套可选：
├── 🐉 【默认】国风米黄（当前 V2.2.0 方案）
├── 🌙 深色玄夜（深蓝紫背景 #1a1a2e，金箔色文字 #d4af37）
└── 🌸 樱粉清新（给女性用户，低饱和柔和粉，不刺眼）

技术实现：
├── 所有颜色变量集中在 styles/variables.css 中（V2.2.0 已经做了，只需扩展）
├── 切换主题时 body 加 class `theme-dark theme-sakura`，CSS 变量覆盖即可
└── safeLS.setItem('xll_theme') 持久化用户选择
```

**预期工作量**：90% 工作在 CSS 变量调整 + 深色 对比度检查（WCAG AA 4.5:1 最小对比度）；10% JS 切换器 + 持久化。
